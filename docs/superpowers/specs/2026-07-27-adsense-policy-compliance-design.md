# AdSense 審査対応 設計ドキュメント

作成日: 2026-07-27
ブランチ: `fix/adsense-policy-compliance`

## 背景

Google AdSense の審査で以下2点を理由に不承認となった。

1. パブリッシャーのコンテンツを含まない画面における Google が配信する広告の扱い
2. 有用性の低いコンテンツ

本ドキュメントは原因の特定結果と修正方針を記録する。

## 原因分析

### 指摘① コンテンツを含まない画面での広告

本番配信 HTML（https://wuwaechotools.com）を実測した結果、トップページの可読テキストは約 300 文字しかない。内容はボタンとラベルのみで、記事的なコンテンツが存在しない。そこに `src/app/layout.tsx` で全ページ共通の AdSense タグが入っている。

悪化要因は次の3点。

- **リワード広告の残骸**: `layout.tsx` が `securepubads.g.doubleclick.net/tag/js/gpt.js` を読み込んでいるが、`AdBonusModal.tsx` の広告ユニットは `/YOUR_NETWORK_CODE/rewarded-bonus` というプレースホルダのまま。存在しないネットワークコードへ配信要求が飛んでいる。
- **報酬型広告の文言がトップに露出**: 「広告を1本最後まで視聴するだけ（約30秒）」「📺 広告で保存枠 +10」。AdSense は広告視聴・クリックへのインセンティブ付与を禁止している。
- **実装が空回りしている**: `AdBonusModal.tsx` は広告を一切表示せず、ボタン1回で報酬を付与する。「広告を見れば特典」と書いてあるのに広告が出ない画面になっている。

### 指摘② 有用性の低いコンテンツ

最も中身のある2ページが意図的に noindex されていた。

| ページ | 実質テキスト量 | 状態 |
|---|---|---|
| `/score-formula` | 約 9,800 字 | `robots: { index: false }`・リンク皆無・sitemap 未登録 |
| `/chardb` | 42 キャラ分のビルドデータ | 同上 |
| `/guide` | 約 4,000 字 | インデックス可 |
| `/` `/supporter` `/contact` `/news` | 各 300〜700 字 | フォーム主体 |

結果として Google がインデックスできるサイト全体は「薄いツール1枚＋ガイド1本」になっていた。`/score-formula` は完全に独自のスコア計算式ドキュメントであり、審査で評価される種類のコンテンツなのに自ら封印していた。

加えて運営者情報ページが存在せず、`/news` の更新履歴も 1 件（2026-07-12）のみで、放置されたサイトの印象を強めていた。

## 方針決定

ユーザーとの議論で以下を決定した。

- **広告視聴ボーナス**: 撤去する。ただし代替収益モデルを併せて設計する
- **コンテンツ対策**: 既存ページの拡充のみ。新規の記事コンテンツは書かない
- **言語**: 日英同時対応

## 設計

### フェーズ1: ポリシー違反の除去

1. `AdBonusModal` を「ボーナス開放モーダル」に作り替える。コメントアウトされた GPT コード・広告状態 UI・`REWARDED_AD_UNIT` 定数を全削除し、無条件で特典を付与する
2. `layout.tsx` から `gpt.js` の読み込みを削除する。リワード広告を使わないため不要
3. 広告文言を日英とも撤去する。対象キー: `bonusAdNote` / `adSaveSlots` / `adLoading` / `adWatching` / `adWatchHint` / `adWatchingSub` / `adError` / `adErrorTip` / `adFreeLabel` / `adRewardsTitle`
4. `GuideClient` の「広告を1本（約30秒）視聴するだけで5分間の特典」を書き換える
5. AdSense タグ自体は残す（審査に必要）。自動広告は管理画面で一旦オフにし、承認後にコンテンツのあるページへ手動配置する

### フェーズ2: コンテンツ拡充（既存ページのみ・日英）

1. **`/score-formula` と `/chardb` を解禁**。noindex を外し、`buildMetadata` / `buildBreadcrumbJsonLd` でメタデータを整備、`sitemap.ts` に追加、ヘッダーメニューとフッターから導線を張る。約1万字が一気にインデックス対象になる、最も費用対効果の高い施策
2. **`/chardb` と `/score-formula` の日英対応**。現在は日本語ハードコードなので `LocaleProvider` + 辞書方式へ寄せる
3. **トップページ下部に解説セクションを新設**（日英・各1,500〜2,500字）。「音骸厳選とは何か」「このツールでできること」「スコアの考え方」「使い方3ステップ」「FAQ」。FAQ には FAQPage JSON-LD を付与する。指摘①②を同時に潰す中核施策
4. **運営者情報ページ `/about` を新設**。非公式ファンツールである旨・運営者・データ出典・更新方針・連絡先を明記
5. **`/guide` の拡充と `/news` の更新履歴追加**

### フェーズ3: 収益モデル

リワード広告はプレースホルダのまま無効化されており、現時点で収益はゼロ。撤去による実損はない。

- **本命**: 承認後の通常ディスプレイ広告を、コンテンツのあるページに手動配置する。トップの解説セクション内、`/guide`、`/score-formula`、`/chardb`。厳選シミュは長時間の滞在が発生するため、1セッションあたりのインプレッションを稼げる。フェーズ2で広告を置ける「面」を作ること自体が収益化の前提になる
- **補助**: 支援リンク（Ko-fi / OFUSE / BOOTH など外部リンク1本）をフッターとメニューに置く。ポリシーリスクゼロ、実装コストもほぼゼロ
- **将来**: AdSense 承認後に Ad Manager を開設し、正規のリワード広告ユニットとして「広告を見るとボーナス延長」を再導入する。ボーナス機能自体は残すため後から追加できる。ただし Ad Manager のリワード広告は別途審査と在庫が必要で、小規模サイトでは実質配信されない可能性が高い

## 検証

- `next build` が通ること
- 配信 HTML に「広告を」「Watch Ad」等のインセンティブ文言が残っていないこと
- `/score-formula` `/chardb` が noindex でなく、sitemap に含まれ、トップから到達できること
- トップページの可読テキストが日英とも大幅に増えていること
- 日英切り替えで新規セクションが両方正しく表示されること

## 対象外

- 新規の記事コンテンツ作成（ユーザー判断で今回は行わない）
- 実際の広告ユニット配置（AdSense 承認後に実施）
- Ad Manager の開設とリワード広告の正規実装（承認後に検討）
