# ホーム: 音骸とメインステータスの変更を分かりやすくする

## 背景

オーナーから「音骸のメインステータスを変更するところが分かりにくい」と指摘があった。今の問題は3つ。

1. 強化中タブの「シギルム　クリティカル率 22.0%」の行がただの文字に見え、押せることが分からない
2. 押すと出るシートに、見出しのないドロップダウンが2つ並ぶだけで、どちらが何か分からない
3. メインステータスは COST ごとに 3〜10 個しかないのに、ドロップダウンに隠れていて、どれがおすすめか一目で分からない

オーナーが選んだ形(2026-10-20):入口をキャラボタンと同じ見た目の板にする。シートの中では、メインステータスをボタンを並べた形で選ぶ。

## 変更対象

- `src/app/HomeClient.tsx`(メイン行の見た目、BuildBar に渡す値)
- `src/components/home/BuildBar.tsx`(設定シートの中身)

触らないもの: `src/components/CustomSelect.tsx`、`src/data/**`、ほかの `src/components/home/*`

## 仕様

### 1. 入口(強化中タブのメイン行)

今の `HomeClient.tsx` のメイン行ボタン(`className="flex items-baseline gap-[10px] ..."`)を、キャラボタン(`BuildBar.tsx` の上段)と同じ見た目の板にする。

```
┌────────────────────────────────────────┐
│ 音骸   シギルム                           │
│ メイン クリティカル率 22.0%        変更 › │
└────────────────────────────────────────┘
```

- 高さ 44px。`[@media(max-height:780px)]:` では 36px(667px でサブステ欄の行が 28px を割らないよう、レビュー時に 38→36 に変更)。背景 `var(--hd-plate)`、角丸 10px、左右の余白 12px。`flex: none`
- 左の列は2行
  - 1行目: 小さいラベル「音骸」(EN: "Echo")+ 音骸名。COST 3 / 1 ではラベルを「ハーモニー」(EN: "Set")にし、ハーモニー名を出す
  - 2行目: 小さいラベル「メイン」(EN: "Main")+ メインステータス名 + 値(今と同じ書式。値は `hd-num` で太字、名前と同じ 13px。低い画面では 12px)
  - ラベルは 11px、`var(--hd-sub)`、幅をそろえる(`min-width` で2行の頭をそろえる)。名前は 13px、`var(--hd-fg)`。長い名前は `truncate`
  - 低い画面(780px 以下)では、ラベルを 10px、名前を 12px にして 36px に収める
- 右端に「変更 ›」(EN: "Change ›")。キャラボタンの「変更 ›」と同じ文字の大きさ・色・記号
- 押すと今と同じく設定シートが開く(キャラ選択シートは閉じる)

### 2. 設定シートの中身

上から順に並べる。

```
音骸とメインステータス                (h2、今のまま)

メインステータス(+25 の値)           (小見出し)
┌────────┐┌────────┐┌────────┐
│★クリ率  ││★クリダメ││ 攻撃力% │
│  22.0% ││  44.0% ││  33.0% │
└────────┘└────────┘└────────┘
 …
★ は選んだキャラのおすすめ             (キャラを選んでいるときだけ出す注記)

音骸   / ハーモニー                    (小見出し)
[ シギルム                ▼ ]          (今の CustomSelect のまま)
[ ハーモニーの選択 ▼ ]                 (cost4MultiSet のときだけ。小見出し「ハーモニー」)

[        閉じる          ]
```

- 小見出しは 12px、`font-bold`、`var(--hd-sub)`。EN は "Main stat (value at +25)" / "Echo" / "Set" / "Set"
- **メインステータスのボタン**
  - 3列のグリッド、すき間 8px
  - 並び順は `MAINSTAT_POOLS[cost]` の順のまま固定する(キャラを変えても位置が動かないように)。今の `mainstatOptions` のような、おすすめを先頭にする並べ替えはしない
  - ボタン1つ: 高さ 56px、角丸 8px、背景 `var(--hd-raise)`。中は2段
    - 上の段: 名前。12px、最大2行。`word-break: keep-all` にし、改行は「ダメージ」「アップ」の手前(`<wbr>`)だけで起こす(レビュー時に追加。「アッ/プ」と割れるのを防ぐため)。(`line-clamp-2`)、行間 1.25
    - 下の段: +25 の値(例 `22.0%`)。13px、`hd-num`、太字
  - 選択中: 背景 `var(--hd-accent)`、文字 `var(--hd-accent-ink)`。`aria-pressed` を付ける
  - おすすめ(`build.mainstat[costKey].recommended` に入っているもの)は、値の前に「★」を付ける(レビュー時に名前の前から移動)。選択中でないときの ★ の色は `var(--hd-accent)`、選択中は文字と同じ色
  - `acceptable` には印を付けない
  - 押すとすぐ `onMainstatChange(key)` を呼ぶ。シートは閉じない
- キャラを選んでいるときだけ、ボタンの下に「★ は {キャラ名} のおすすめ」(EN: "★ = recommended for {name}")を 11px、`var(--hd-sub)` で出す
- 音骸・ハーモニーの CustomSelect は今のまま。上に小見出しを付けるだけ

### 3. HomeClient から BuildBar に渡すもの

- `mainstatOptions: SelectOption[]` をやめ、次の形の `mainstatChoices` を渡す

  ```ts
  { key: string; name: string; valueText: string; recommended: boolean }[]
  ```

  - `name`: JA は `m.label`、EN は `MAINSTAT_LABEL_EN[m.key] ?? m.label`
  - `valueText`: `%` のときは `value.toFixed(1)` + `%`、ほかは今のメイン行と同じ書式
- おすすめの注記のために、キャラ名(なければ空文字)を BuildBar に渡す。すでにある `charName` は「キャラなし」を含むので、別に `recommendFor: string`(キャラなしのときは `''`)を渡す
- `mainstatOptions` がほかで使われていなければ、`useMemo` ごと消す

## 受け入れ条件

- `npx tsc --noEmit` と `npm run build` が通る
- `grep -n "mainstatOptions" src/app/HomeClient.tsx src/components/home/BuildBar.tsx` が0件
- 以下はブラウザで Claude Code が確かめる
  - メイン行が板になっていて「変更 ›」が見える。押すと設定シートが開く
  - COST 4 で 6個、COST 3 で 10個、COST 1 で 3個のボタンが出る。押すとすぐメイン行の表示が変わり、シートは開いたまま
  - キャラ「心」を選ぶと、おすすめに ★ が付き、注記にキャラ名が出る。キャラなしでは ★ も注記も出ない
  - EN でもボタンの名前が2行以内に収まる(はみ出さない)
  - 幅 390 と 375、高さ 844 / 780 / 720 / 667 で、サブステ 0 / 5 個のとき、強化中タブの真ん中のエリアが重ならず、スクロールしない(`spec-home-n5.md` 追加修正 7 の条件をそのまま満たす)

## 対象外

- 音骸の選び方そのもの(CustomSelect のドロップダウン)は変えない
- COST の切り替え、キャラ選択シートは変えない
- メインステータスの値やおすすめのデータは変えない

## 想定される落とし穴

- メイン行が 24px → 44px(低い画面では 36px)に増えるので、真ん中のエリアが狭くなる。667px では SlotList の行が最小の 28px 近くまで縮む。最後の受け入れ条件で真ん中のエリアがスクロールするようなら、勝手に寸法を変えずに止めて報告する
- COST を切り替えたとき、メインステータスは `onCostChange` の中で先頭に戻している(`HomeClient.tsx`)。この処理は消さない
- ボタンの色は `var(--hd-accent)` を使う。CustomSelect と違い 16進数の文字列は要らない
